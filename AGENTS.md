# Working in this repository

DiaLearn is a tutoring marketplace running on `TanStack frontend → NestJS REST
API → PostgreSQL`. It began as a Supabase/Lovable Cloud demo; the frontend no
longer speaks to Supabase at all. Read `docs/ARCHITECTURE_MIGRATION.md` before
changing anything structural — it is the audit the migration plan was built on.

This project is **no longer connected to Lovable**. The sync constraint that
used to live in this file (never rewrite published history) no longer applies.

## Before you commit

```sh
bun run lint          # must be 0 errors
bun run test          # must be green
bun run typecheck     # must be 0 errors
bun run build
```

`typecheck` is a plain `tsc --noEmit` and is expected to be clean. It used to be
a ratchet over a baseline of known errors caused by a stale generated
`types.ts`; that file is gone and the baseline reached zero, so the ratchet was
replaced by the real check. Do not reintroduce a baseline — fix the error.

## Do not edit

| Path                                     | Why                                                                                                                                                        |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routeTree.gen.ts`                   | Generated by the TanStack router plugin.                                                                                                                   |
| `vite.config.ts`                         | A thin wrapper that injects the TanStack, Tailwind, nitro and env plugins. Adding plugins manually breaks the build. Tests use `vitest.config.ts` instead. |
| `supabase/migrations/**`                 | Historical record of the schema, still the source of truth for it. Append new files; never edit applied ones.                                              |
| `src/components/ui/**`, `src/styles.css` | The design system. Changes here must not change how the product looks.                                                                                     |

## Where the types live

The frontend owns its own types now; nothing is generated from the database.

- `src/lib/domain-types.ts` — the domain enums (`AppRole`, `BookingStatus`,
  `AssignmentStatus`, …). These mirror PostgreSQL enums. Before changing one,
  check the real enum with `select enumlabel from pg_enum` — several screens
  once filtered on statuses that never existed, and the compiler could not say
  so while the generated types were stale.
- `src/lib/database-types.ts` — row shapes and stored-procedure result shapes.
- `src/lib/governance-types.ts` — the admin governance surface.

A `jsonb` column is typed `Json`, not `string[]`. Narrow it at the point of use;
the column has no check constraint, so a narrower declaration is a guess.

## Rules

1. Never delete a route because it has not been migrated yet.
2. Never invent business rules. Existing behaviour is the source of truth —
   much of it lives in PL/pgSQL, not TypeScript. The NestJS repositories call
   the `SECURITY DEFINER` functions rather than reimplementing them.
3. Never hardcode pricing, commissions, currencies, subjects, curricula,
   availability or notification templates.
4. Every step must be independently testable and reversible.
5. Secrets never enter source, logs or the frontend bundle. Anything named
   `VITE_*` is inlined into the browser bundle at build time.

## The coupling guard

`test/contract/no-supabase.test.ts` was the migration's ratchet: an inventory of
45 stored procedures and 35 tables that could only shrink. It is now empty and
guards the other direction — it fails if anything reintroduces a Supabase
client, a direct PostgREST call, or a `VITE_*` secret.
