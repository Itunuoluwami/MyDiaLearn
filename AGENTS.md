# Working in this repository

DiaLearn is a tutoring marketplace mid-migration from a Supabase/Lovable Cloud
demo to `TanStack frontend → NestJS REST API → PostgreSQL`. Read
`docs/ARCHITECTURE_MIGRATION.md` before changing anything structural — it is the
audit the migration plan is built on.

This project is **no longer connected to Lovable**. The sync constraint that
used to live in this file (never rewrite published history) no longer applies.

## Before you commit

```sh
bun run lint          # must be 0 errors
bun run test          # must be green
bun run typecheck:ratchet
bun run build
```

`typecheck:ratchet` is not a plain `tsc`. The repo carries 83 known type errors
caused by a stale generated `types.ts`; the script fails only if that count
**rises**. When the types are regenerated, lower `BASELINE` in
`scripts/typecheck-ratchet.mjs` to lock the gain in.

## Do not edit

| Path                                     | Why                                                                                                                                                        |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/integrations/supabase/types.ts`     | Generated by `supabase gen types`. Regenerate, never hand-patch.                                                                                           |
| `src/routeTree.gen.ts`                   | Generated by the TanStack router plugin.                                                                                                                   |
| `vite.config.ts`                         | A thin wrapper that injects the TanStack, Tailwind, nitro and env plugins. Adding plugins manually breaks the build. Tests use `vitest.config.ts` instead. |
| `supabase/migrations/**`                 | Historical record. Append new files; never edit applied ones.                                                                                              |
| `src/components/ui/**`, `src/styles.css` | The design system. The migration must not change how the product looks.                                                                                    |

## Migration rules

1. Never remove Supabase functionality before its replacement is implemented
   **and verified**.
2. Never delete a route because it has not been migrated yet.
3. Never invent business rules. Existing behaviour is the source of truth —
   most of it lives in PL/pgSQL, not TypeScript.
4. Never hardcode pricing, commissions, currencies, subjects, curricula,
   availability or notification templates.
5. Every step must be independently testable and reversible.
6. Secrets never enter source, logs or the frontend bundle. Anything named
   `VITE_*` is inlined into the browser bundle at build time.

## The coupling ratchet

`test/contract/supabase-coupling.test.ts` freezes the Supabase surface at 45
stored procedures and 35 tables. It fails in **both** directions: you cannot add
new coupling quietly, and you cannot mark a domain migrated until its entries are
deleted. Expect the list to shrink. When it is empty, the migration is done.
